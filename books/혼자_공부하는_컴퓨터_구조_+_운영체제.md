# Chapter 01 컴퓨터 구조 시작하기

| Term & Category                     | Definition, Role & Example                                                                                                                                                                       |
| :---------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **컴퓨터의 핵심 부품**              | 중앙처리장치(CPU), 주기억장치(메모리), 보조기억장치(secondary storage), 입출력장치(input/output(I/O) device)                                                                                     |
| **메모리** _(main memory)_          | 현재 실행되는 프로그램의 명령어와 데이터를 저장하는 부품이다. (e.g., `RAM(Random Access Memory)`, `ROM(Read Only Memory)`)                                                                       |
| **CPU** _(Central Processing Unit)_ | 메모리에 저장된 명령어를 읽어 들이고, 읽어 들인 명령어를 해석하고, 실행하는 부품이다. (e.g., `산술논리연산장치(ALU; Arithmetic Logic Unit)`, `레지스터(Register)`, `제어장치(CU; Control Unit)`) |
| **보조기억장치**                    | 전원이 꺼져도 보관할 프로그램을 저장하는 부품이다.                                                                                                                                               |
| **입출력장치**                      | 컴퓨터 외부에 언결되어 컴퓨터 내부와 정보를 교환할 수 있는 부품이다.                                                                                                                             |
| **시스템 버스** _(system bus)_      | 컴퓨터의 네 가지 핵심 부품들이 서로 정보를 주고 받는 통로이다.                                                                                                                                   |

| **컴파일 언어** _(Execution)_           | 컴파일러에 의해 소스 코드 전체가 저급 언어로 변환되어 실행되는 언어 (C, C++).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

# Chapter 04 CPU의 작동 원리

| Term & Category                                             | Definition, Role & Example                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| :---------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ALU**                                                     | 레지스터로부터 피연산자를 받아들이고, 제어장치로부터 제어 신호를 받아들임. ALU는 연산 결과와 플래그를 내보냄                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **플래그** _(flag)_                                         | 연산 결과에 대한 추가적인 상태 정보(e.g., `부호 플래그`, `제로 플래그`, `캐리 플래그`, `오버플로우 플래그`, `인터럽트 플래그`, `슈퍼바이저 플래그`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **제어장치가 받아들이는 정보**                              | 클럭, 현재 수행할 명령어, 플래그, 제어 신호                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **제어장치가 내보내는 정보**                                | CPU 내부와 외부로 제어 신호를 내보냄.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **레지스터의 종류**                                         | • **프로그램 카운터(PC; Program Counter):** 메모리에서 읽어 들일 명령어의 주소를 저장.<br>• **명령어 레지스터(IR;Instruction Register):** 방금 메모리에서 읽어 들인 명령어를 저장하는 레지스터.<br>• **메모리 주소 레지스터(MAR; Memory Address Register):** 메모리의 주소를 저장하는 레지스터.<br>• **메모리 버퍼 레지스터(MBR; Memory Buffer Register):** 메모리와 주고받을 값(데이터와 명령어)을 저장하는 레지스터.<br>• **플래그 레지스터(flag register):** 연산 결과 또는 CPU 상태에 대한 부가적인 정보를 저장하는 레지스터. <br>• **범용 레지스터(general purpose register):** 다양하고 일반적인 상황에서 자유롭게 사용할 수 있는 레지스터.<br>• **스택 포인터(stack pointer):** 스택의 꼭대기를 가리키는 레지스터.<br>• **베이스 레지스터(base-register):** 기준 주소로서의 역할을 함. |
| **명령어 사이클** _(instruction cycle)_                     | 하나의 명령어가 처리되는 주기로, 인출, 실행, 간접, 인터럽트 사이클로 구성.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **인터럽트** _(interrupt)_                                  | CPU의 정상적인 작업을 방해하는 신호                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **인터럽트의 종류**                                         | • **동기 인터럽트 (synchronous interrupts):** CPU에 의해 발생하는 인터럽트(예외).<br>• **비동기 인터럽트(asynchronous interrupts):** 입출력장치에 의해 발생하는 인터럽트(하드웨어 인터럽트).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **인터럽트 서비스 루틴** _(ISR; Interrupt Service Routine)_ | 인터럽트를 처리하기 위한 동작들로 이루어진 프로그램(인터럽트 핸들러, interrupt handler)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **예외의 종류**                                             | 예외가 발생하면 CPU는 하던 일을 중단하고 해당 예외를 처리.<br>• **폴트(fault):** 예외를 처리한 직후 예외가 발생한 명령어부터 실행을 재개하는 예외.<br>• **트랩(trap):** 예외를 처리한 직후 예외가 발생한 명령어의 다음 명령어부터 실행을 재개하는 예외.<br>• **중단(abort):** CPU가 실행 중인 프로그램을 강제로 중단시킬 수밖에 없는 심각한 오류를 발견했을 때 발생하는 예외.<br>• **소프트웨어 인터럽트(software interrupt):** 시스템 호출이 발생했을 때 나타남.                                                                                                                                                                                                                                                                                                                             |

# Chapter 05 CPU 성능 향상 기법

클럭 속도가 높은 CPU는 빠르게 동작한다.

| Term & Category                                                  | Definition, Role & Example                                                                                                                                                                                                                                                                                              |
| :--------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **클럭 속도를 높이는 방법**                                      | CPU의 코어와 스레드 수를 늘리기                                                                                                                                                                                                                                                                                         |
| **코어**                                                         | CPU 내에서 명령어를 실행하는 부품                                                                                                                                                                                                                                                                                       |
| **멀티코어** _(multi-core)_                                      | 여러 개의 코어를 포함하는 CPU(멀티코어 프로세서)                                                                                                                                                                                                                                                                        |
| **스레드**                                                       | 실행 흐름의 단위<br>• **하드웨어적 스레드:** 하나의 코어가 동시에 처리하는 명령어 단위.<br>• **소프트웨어적 스레드:** 하나의 프로그램에서 독립적으로 실행되는 단위.                                                                                                                                                     |
| **멀티스레드(multithread) 프로세서**                             | 하나의 코어로 여러 개의 명령어를 동시에 실행할 수 있는 CPU                                                                                                                                                                                                                                                              |
| **명령어 병렬 처리 기법** _(ILP; Instruction-Level Parallelism)_ | 명령어를 동시에 처리하여 CPU를 한시도 쉬지 않고 작동시키는 방법<br>• **명령어 파이프라이닝:** 동시에 여러 개의 명령어를 겹쳐 실행하는 기법.<br>• **슈퍼스칼라:** 여러 개의 명령어 파입프라인을 두는 기법.<br>• **비순차적 명령어 처리 기법:** 파이프라인의 중단을 방지하기 위해 명령어를 순차적으로 처리하지 않는 기법. |
| **명령어 집합 구조** _(ISA; Instruction Set Architecture)_       | CPU의 언어이자 하드웨어가 소프트웨어를 어떻게 이해할지에 대한 약속<br>• **CISC(Complex Instruction Set Computer):** 복잡하고 다양한 종류의 가변 길이 명령어 집합을 활용.<br>• **RISC(Reduced Instruction Set Computer):** 단순하고 적은 종류의 고정 길이 명령어 집합을 활용. |

# Chapter 06 CPU 메모리와 캐시 메모리

클럭 속도가 높은 CPU는 빠르게 동작한다.

| Term & Category | Definition, Role & Example |
| :--------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **휘발성 저장 장치** _(volatile memory)_ | 전원을 끄면 저장된 내용이 사라지는 저장 장치 (e.g., `RAM`, `ROM`) |
| **보조기억장치** _(non-volatile memory)_ | 전원이 꺼져도 저장된 내용이 유지되는 저장 장치 |
| **RAM의 종류** | • **DRAM(Dynamic RAM):** 시간이 지나면 저장된 데이터가 점차 사라지는 RAM.<br>• **SRAM(Static RAM):** 시간이 지나도 저장된 데이터가 사라지지 않는 RAM.<br>• **SDRAM(Synchronous Dynamic RAM):** 클럭과 동기화된 DRAM.<br>• **DDR SDRAM(Double Data Rate SDRAM):** SDR SDRAM에 비해 대역폭이 두 배 넓음. |
| **주소의 종류** | • **물리 주소(physical address):** 메모리 하드웨어가 사용하는 주소.<br>• **논리주소(logical address):** CPU와 실행 중인 프로그램이 사용하는 주소|
| **메모리 관리 장치** _(MMU; Memory Management Unit)_ | 논리 주소를 물리 주소로 변환 |
| **베이스 레지스터** | 프로그램의 첫 물리 주소를 저장 |
| **한계 레지스터** _(limit register)_ | 실행 중인 프로그램의 논리 주소의 최대 크기를 저장 |
| **저장 장치 계층 구조** _(memory hierachy)_ | 각기 다른 용량과 성능의 저장 장치들을 계층화하여 표현한 구조. |
| **캐시 메모리** _(cache memory)_ | CPU의 연산 속도와 메모리 접근 속도의 차이를 줄이기 위한 저장 장치<br>• **캐시 적중률** _(cache hit ratio)_ 이 높으면 CPU의 메모리 접근 횟수를 줄일 수 있다.<br>• 캐시 메모리는 **참조 지역성의 원리** _(locality of regerence, principle of locality)_ 에 따라 데이터를 예측하여 캐시 적중률을 높인다. |

# Chapter 07 보조기억장치

| Term & Category | Definition, Role & Example |
| :--------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 보조기억장치의 종류 | 하드 디스크, 플래시 메모리(e.g., `USB 메모리`, `SD 카드`, `SSD`)|
| **하드 디스크(HDD; Hard Disk Drive)의 구성 요소** | • **플래터 (platter):** 하드 디스크에서 실질적으로 데이터가 저장되는 동그란 원판<br>&nbsp;&nbsp;├── **트랙 (track):** 플래터를 여러 동심원으로 나누었을 때 그 중 하나의 원 <br>&nbsp;&nbsp;├── **섹터 (sector):** 트랙의 한 조각<br>&nbsp;&nbsp;└── **실린더 (cylinder):** 여러 겹의 플래터 상에서 같은 트랙이 위치한 곳을 모아 연결한 논리적 단위 <br>• **스핀들 (spindle):** 플래터를 회전시키는 구성 요소<br>• **헤드 (head):** 플래터를 대상으로 데이터를 읽고 쓰는 구성 요소<br>• **디스크 암 (disk arm):** 헤드를 원하는 위치로 이동시키는 구성 요소 |
| **하드 디스크이 데이터 접근 시간** | • **탐색 시간(seek time):** 접근하려는 데이터가 저장된 트랙까지 헤드를 이동시키는 시간 <br> • **회전 지연(rotational latency):** 헤드가 있는 곳으로 플래터를 회전시키는 시간 <br> • **전송 시간(transfer time):** 하드 디스크와 컴퓨터 간에 데이터를 전송하는 시간 |
| **플래시 메모리(Flash Memory)** | • **종류**<br>&nbsp;&nbsp;├── **SLC (Single Level Cell):** 한 셀에 1비트 저장<br>&nbsp;&nbsp;├── **MLC (Multiple Level Cell):** 한 셀에 2비트 저장<br>&nbsp;&nbsp;└── **TLC (Triple-Level Cell):** 한 셀에 3비트 저장<br>• **동작 단위:** 읽기/쓰기는 **페이지(page)** 단위, 삭제는 **블록(block)** 단위 |
| **RAID(Redundant Array of Independent Disks)** | 데이터의 안전성 혹은 높은 성능을 위해 여러 하드 디스크나 SSD를 마치 하나의 장치처럼 사용하는 기술<br>• **RAID 0:** 여러 개의 보조기억장치에 데이터를 단순히 병렬로 분산하여 저장하는 방식<br>• **RAID 1:** 완전한 복사본을 만드는 방식 <br>• **RAID 4:** 패리티를 저장한 장치를 따로 두는 방식<br>• **RAID 5:** 패리티를 분산하여 저장하는 방식<br>• **RAID 6:** 서로 다른 두 개의 패리티를 두는 방식|
| **패리티 비트** _(parity bit)_ | 오류를 검출하고 복구하기 위한 정보 |

# Chapter 08 입출력장치

입출력장치는 장치 컨트롤러(device controller)를 통해 컴퓨터 내부와 정보를 주고 받는다.

| Term & Category | Definition, Role & Example |
| :--------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **장치 컨트롤러의 역할** | • CPU와 입출력장치 간의 통신 중개 <br> • 오류 검출 <br> • 데이터 버퍼링: 전송률이 높은 장치와 낮은 장치 사이에 주고 받는 데이터를 버퍼(buffer)라는 임시 저장공간에 저장하여 전송률을 비슷하게 맞추는 방법. |
| **장치 컨트롤러의 내부** | • **데이터 레지스터(data register):** CPU와 입출력장치 사이에 주고받을 데이터가 담기는 레지스터<br>• **상태 레지스터(status register):** 입출력장치가 입출력 작업을 할 준비가 되었는지, 입출력 작업이 완료되었는지 등의 상태 정보가 저장<br>• **제어 레지스터(control register):** 입출력장치가 수행할 내용에 대한 제어 정보와 명령을 저장 |
| **장치 드라이버(device driver)** | 장치 컨트롤러가 컴퓨터 내부와 정보를 주고받을 수 있게 하는 프로그램 |
| **장치 컨트롤러가 CPU와 정보를 주고 받는 방법** | • **프로그램 입출력(programmed I/O):** 프로그램 속 명령어로 입출력장치를 제어하는 방법<br>&nbsp;&nbsp;├── **메모리 맵 입출력(memory-mapped I/O):** 메모리에 접근하기 위한 주소 공간과 입출력장치에 접근하기 위한 주소 공간을 하나의 주소 공간으로 간주하는 입출력 방식<br>&nbsp;&nbsp;└── **고립형 입출력(isolated I/O):** 메모리에 접근하기 위한 주소 공간과 입출력장치에 접근하기 위한 주소 공간을 분리하는 입출력 방식<br>• **인터럽트 기반 입출력(Interrupt-Driven I/O):** 인터럽트를 기반으로 입출력을 수행하는 방법<br>• **DMA(Direct Memory Access) 입출력:** CPU를 거치지 않고 메모리와 입출력장치 간의 데이터를 주고받는 입출력 방식|
| **입출력 버스(input/output bus)** | 입출력장치와 컴퓨터 내부를 연결 짓는 통로로, 입출력 작업 과정에서 시스템 버스 사용 횟수를 줄여줌. |

# Chapter 10 프로세스와 스레드

| Term & Category | Definition, Role & Example |
| :--------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **프로세스(process)** | 실행 중인 프로그램<br>&nbsp;&nbsp;├── **포그라운드 프로세스(foreground process):** 사용자가 볼 수 있는 공간에서 실행되는 프로세스<br>&nbsp;&nbsp;└── **백그라운드 프로세스(background process):** 사용자가 보지 못하는 뒤편에서 실행되는 프로세스 <br><br> 사용자 영역에 배치된 프로세스 <br>&nbsp;&nbsp;├── **코드 영역(code segment):** 기계어로 이루어진 명령어가 저장<br>&nbsp;&nbsp;├── **데이터 영역(data segment):** 프로그램이 실행되는 동안 유지할 데이터가 저장되는 공간(e.g., `전역변수(global variable)`)<br>&nbsp;&nbsp;├── **힙 영역(heap segment):** 프로그래머가 직접 할당할 수 있는 저장 공간<br>&nbsp;&nbsp;└── **스택 영역(stack segment):** 데이터를 일시적으로 저장하는 공간(e.g., `매개 변수`, `지역 변수`) <br><br> 프로세스가 가질 수 있는 상태<br>&nbsp;&nbsp;├──**생성 상태(new):** 프로세스를 생성 중인 상태<br>&nbsp;&nbsp;├──**준비 상태(ready):** 아직 자신의 차례가 아니기에 기다리고 있는 상태<br>&nbsp;&nbsp;├──**실행 상태(running):** CPU를 할당 받아 실행 중인 상태<br>&nbsp;&nbsp;├──**대기 상태(blocked):** 입출력장치의 작업을 기다리는 상태<br>&nbsp;&nbsp;└──**종료 상태(terminated):** 프로세스가 종료된 상태<br><br> • **부모 프로세스(parent process):** 프로세스가 다른 프로세스를 생성한 경우 새 프로세스를 생성한 프로세스 <br> • **자식 프로세스(child process):** 부모 프로세스에 의해 생성된 프로세스<br> • 많은 운영체제는 프로세스가 프로세스를 낳는 **프로세스 계층 구조**로 프로세스들을 관리한다.
| **프로세스 제어 블록(PCB; Process Control Block)** | 운영체제가 프로세스를 제어하기 위해 정보를 저장해 놓는 곳으로, 프로세스의 상태 정보를 저장하는 자료 구조 |
| **PCB에 담기는 정보** | 프로세스 ID(PID; Process ID), 레지스터 값, 프로세스 상태, CPU 스케줄링 정보 메모리 관리 정보, 사용한 파일과 입출력 장치 목록 |
| **문맥 교환(context switching)** | 기존 프로세스의 문맥을 PCB에 백업하고, 새로운 프로세스를 실행하기 위해 문맥을 PCB로부터 복구하여 새로운 프로세스를 실행하는 것 |

# Chapter 11 CPU 스케줄링

| Term & Category | Definition, Role & Example |
| :--------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CPU 스케줄링(CPU scheduling)** | 운영체제가 프로세스들에게 공정하고 합리적으로 CPU 자원을 배분하는 방법 <br> 프로세스의 중요도에 맞게 프로세스가 CPU를 이용할 수 있도록 하기 위해 운영체제는 프로세스마다 **우선순위(prioirty)** 를 부여하고, 운영체제는 각 프로세스의 PCB에 우선순위를 명시한다. <br><br> • 운영체제는 효율적인 스케줄링을 위해 **스케줄링 큐(scheduling queue)** 를 사용한다.<br>&nbsp;&nbsp;├── **준비 큐(ready queue):** CPU 할당을 기다리는 프로세스들을 위한 큐<br>&nbsp;&nbsp;└── **대기 큐(waiting queue):** 입출력장치를 이용하기 위해 대기 상태에 접어든 프로세스들을 위한 큐  <br><br> • **선점형 스케줄링(preemptive scheduling):** 프로세스가 이용 중인 자원을 빼앗을 수 있다.(프로세스가 CPU를 비롯한 자원을 사용하고 있더라도 운영체제가 프로세스로부터 자원을 강제로 빼앗아 다른 프로세스에 할당할 수 있는 스케줄링 방식) <br> • **비선점형 스케줄링(non-preemptive scheduling):** 프로세스가 이용중인 자원을 빼앗을 수 없다.(하나의 프로세스가ㅏ 자원을 사용하고 있다면 그 프로세스가 종료되거나 스스로 대기 상태에 접어들기 전까진 다른 프로세스가 끼어들 수 없는 스케줄링 방식) <br><br> • CPU 스케줄링 알고리즘의 종류 <br>&nbsp;&nbsp;├── **선입 선처리 스케줄링(FCFS 스케줄링; First Come First Served Scheduling)** 알고리즘: 준비 큐에 삽입된 순서대로 CPU를 할당하는 비선점형 스케줄링 방식<br>&nbsp;&nbsp;├── **최단 작업 우선 스케줄링(SJF 스케줄링; Shortest Job First Scheduling)** 알고리즘: 준비 큐에 삽입된 프로세스들 중 CPU 사용 시간의 길이가 가장 짧은 프로세스부터 CPU를 할당하는 스케줄링 방식 <br>&nbsp;&nbsp;├── **라운드 로빈 스케줄링(round robin scheduling)** 알고리즘: 정해진 시간만큼만 돌아가며 CPU를 할당하는 선점형 스케줄링 방식<br>&nbsp;&nbsp;├── **최소 잔여 시간 우선 스케줄링(SRT; Shortest Remaining Time scheduling)** 알고리즘: 프로세스들은 정해진 타임 슬라이스만큼 CPU를 사용하되, CPU를 사용할 다음 프로세스로든 남아있는 작업 시간이 가장 적은 프로세스가 선택<br>&nbsp;&nbsp;├── **우선순위 스케줄링(priority scheduling)** 알고리즘: 가장 높은 우선순위를 가진 프로세스에 CPU를 할당하는 방식<br>&nbsp;&nbsp;│&nbsp;&nbsp;├── **문제점:** 기아(starvation) 현상 — 우선순위가 낮은 프로세스가 우선순위가 높은 프로세스들에 의해 실행이 계속해서 연기되는 현상<br>&nbsp;&nbsp;│&nbsp;&nbsp;└── **해결책:** 에이징(aging) 기법 — 오랫동안 대기한 프로세스의 우선순위를 점차 높이는 방식<br>&nbsp;&nbsp;├── **다단계 큐 스케줄링(multilevel queue scheduling)** 알고리즘: 우선순위별로 준비 큐를 여러 개 사용하는 스케줄링 방식<br>&nbsp;&nbsp;└── **다단계 피드백 큐 스케줄링(multilevel feedback queue scheduling)** 알고리즘: 프로세스들이 큐 사이를 이동할 수 있는 다단계 큐 스케줄링 |

# Chapter 12 프로세스 동기화

| Term & Category | Definition, Role & Example |
| :--------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **동기화(synchronization)** | 특정 자원에 접근할 때 한 개의 프로세스만 접근하게 하거나 프로세스를 올바른 순서대로 실행하게 하는 것 <br><br> • 동기화를 위한 대표적인 도구<br>&nbsp;&nbsp;├── **뮤텍스 락(Mutex lock; MUTual EXclusion lock):** 임계구역을 잠금으로써 프로세스 간의 상호 배제를 위한 도구.(`acquire 함수`, `release 함수`)<br>&nbsp;&nbsp;├── **세마포:** 공유 자원이 여러 개 있는 임계 구역 문제도 해결할 수 있는 동기화 도구.(`wait 함수`, `signal 함수`)<br>&nbsp;&nbsp;└── **모니터(monitor):** 세마포에 비해 사용자가 사용하기 편리한 동기화 도구로 조건 변수(conditional variable)를 사용. |
| **공유 자원(shared resource)** | 공동으로 사용하는 자원으로, 전역 변수가 될 수도 이쏙, 파일이 될 수도 있고, 입출력장치, 보조기억장치가 될 수도 있다. |
| **임계구역(critical section)** | 공유 자원에 접근하는 코드 중 동시에 실행하면 문제가 발생하는 코드 영역을 의미한다. 임계 구역에 진입한 프로세스가 있다면 다른 프로세스는 임계 구역 밖에서 기다려야 한다. |
| **상호 배제(mutual exclusion)** | 한 프로세스가 임계 구역에서 작업 중이면 다른 프로세스가 임계 구역에 들어갈 수 없도록 제어하는 것 |

# Chapter 13 교착상태

| Term & Category | Definition, Role & Example |
| :--------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **교착 상태(deadlock)** | 일어나지 않을 사건을 기다리며 무한히 대기하는 현상을 의미 <br><br> • 발생 조건 <br>&nbsp;&nbsp;├── **상호 배제(mutual exclusion):** 한 프로세스가 사용하는 자원을 다른 프로세스가 사용할 수 없는 상태<br>&nbsp;&nbsp;├── **점유와 대기(hold and wait):** 자원을 할당받은 상태에서 다른 자원을 할당받기를 기다리는 상태<br>&nbsp;&nbsp;├── **비선점(nonpreemptive):** 어떤 프로세스도 다른 프로세스의 자원을 강제로 빼앗지 못해서 교착상태가 발생한 상태<br>&nbsp;&nbsp;└── **원형 대기(circular wait):** 프로세스들이 원의 형태로 자원을 대기하는 것. <br><br> • 해결 방법<br>&nbsp;&nbsp;├── **교착 상태 예방:** 교착 상태의 발생 조건 중 하나를 충족하지 못하게 하는 방법<br>&nbsp;&nbsp;├── **교착 상태 회피:** 교착상태가 발생하지 않을 정도로만 자원을 할당하는 방법;└── **교착상태 검출 후 회복:** 운영체제는 교착 상태 발생 여부를 주기적으로 검사하고, 교착상태가 발생하면 그때그때 회복하는 방법.|
| **식사하는 철학자 문제(dining philosophers problem)** | 교착 상태의 발생을 보여주는 예시 |
| **자원 할당 그래프(resource-allocation graph)** | 교착 상태를 표현할 수 있는 그림 |

# Chapter 14 가상메모리

| Term & Category | Definition, Role & Example |
| :--------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **스와핑(swapping)** | 메모리에서 사용되지 않는 일부 프로세스를 보조기억장치로 내보내고 실행할 프로세스를 메모리로 들어보내는 메모리 관리 기법 |
| **비어 있는 메모리 공간에 프로세스를 연속적으로 할당하는 방식** | • **최초 적합(first fit):** 최초로 발견한 적재 가능한 빈 공간에 프로세스를 배치하는 방식 <br> • **최적 적합(best fit):** 프로세스가 적재될 수 있는 가장 작은 공간에 프로세스를 배치하는 방식 <br> • **최악 적합(worst fit):** 프로세스가 적재될 수 있는 가장 큰 공간에 프로세스를 배치하는 방식
| **외부 단편화(external fragmentation)** | 프로세스를 할당하기 어려울 만큼 작은 메모리 공간들로 인해 메모리가 낭비되는 현상 <br> (cf. `내부단편화`: 프로세스가 필요한 양보다 더 큰 메모리가 할당되어서 프로세스에서 사용하는 메모리 공간이 낭비되는 상황) |
| **가상 메모리(virtual memory)** | 실행하고자 하는 프로그램을 일부만 메모리에 적재하여 실제 물리 메모리 크기보다 더 큰 프로세스를 실행할 수 있게 하는 기술 |
| **페이징(paging)** | 메모리 물리 주소 공간을 **프레임(frame)** 단위로 자르고 프로세스의 논리 주소 공간을 **페이지(page)** 단위로 자른 뒤 각 페이지를 프레임에 할당하는 가상 메모리 관리 기법 |
| **페이지 테이블(page table)** | • 페이징 기법에서 사용되는 자료구조로서, 프로세스의 페이지 정보를 저장하고 있는 테이블이다. <br> • 페이지 테이블을 통해 페이지가 적재된 프레임을 찾을 수 있다.<br> • **페이지 테이블 엔트리(page table entry):** 페이지 테이블의 각각의 행들<br> • 페이지 테이블에 포함된 내용: <br>&nbsp;&nbsp;├── **유효 비트(valid bit):** 해당 페이지에 접근이 가능한지 여부를 알려준다.<br>&nbsp;&nbsp;│&nbsp;&nbsp;└── **페이지 폴트(page fault):** CPU가 유효 비트가 0인 메모리에 적재되어 있지 않은 페이지로 접근하는 경우 발생하는 예외(Exception)<br>&nbsp;&nbsp;├── **보호 비트(protection bit):** 페이지 보호 기능을 위해 존재하는 비트<br>&nbsp;&nbsp;├── **참조 비트(reference bit):** CPU가 이 페이지에 접근한 적이 있는지 여부를 나타낸다.<br>&nbsp;&nbsp;└── **수정 비트(modified bit):** 해당 페이지에 데이터를 쓴 적이 있는지 없는지 수정 여부를 알려준다. |
| **페이지 테이블 베이스 레지스터(PTBR; Page Table Base Register)** | 각 프로세스의 페이지 테이블이 적재된 주소를 가리킨다. |
| **TLB(Translation Lookaside Buffer)** | 페이지 테이블의 캐시 메모리 역할을 수행하기 위해 페이지 테이블의 일부를 저장한다. |
| **요구 페이징(demand paging)** | 프로세스를 메모리에 적재할 때 처음부터 모든 페이지를 적재하지 않고 필요한 페이지만을 메모리에 적재하는 기법. |
| **페이지 교체 알고리즘** | • **FIFO 페이지 교체 알고리즘(First-In First-Out Page Replacement Algorithm)**: 적재된  페이지 순서대로 교체하는 알고리즘<br> • **최적 페이지 교체 알고리즘(optimal page replacement algorithm):** 앞으로의 사용 빈도가 가장 낮은 페이지를 교체하는 알고리즘<br> • **LRU 페이지 교체 알고리즘(Least Recently Used Page Replacement Algorithm):** 가장 오랫동안 사용되지 않은 페이지를 교체하는 알고리즘|
| **스래싱(thrashing)** | 프로세스가 실제 실행되는 시간보다 페이징에 더 많은 시간을 소요하여 성능이 저해되는 문제(지나치게 빈번한 페이지 교체로 인해 CPU 이용률이 낮아지는 문제) |
| **프레임 할당 방식** | • **균등 할당(equal allocation):** 모든 프로세스에 동일한 프레임을 배분하는 방식<br> • **비례 할당(proportional allocation):** 프로세스의 크기에 따라 프레임을 배분하는 방식<br> • **작업 집합 모델 기반 프레임 할당 방식(working set model):** 작업 집합(working set; 실행 중인 프로세스가 일정 시간 동안 참조한 페이지의 집합)의 크기만큼만 프레임을 할당하는 방식<br> • **페이지 폴트율 기반 프레임 할당 방식(PFF; Page-Fault Frequency):** 페이지 폴트율에 상한선과 하한선을 정하고 그 내부 범위 안에서만 프레임을 할당하는 방식 |

# Chapter 15 파일 시스템

| Term & Category | Definition, Role & Example |
| :--------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **파일(file)** | 의미 있고 관련 있는 정보를 모은 논리적인 단위 |
| **파일 속성(file attribute)** | 파일과 관련된 다양한 부가 정보(e.g., `파일 형식`, `위치`, `크기`) |
| **파일 유형** | 운영체제가 인식하는 파일 종류 <br> 운영체제는 파일의 확장자(extension)를 통해 파일의 유형을 파악할 수 있다. |
| **디렉터리(directory)** | 여러 개의 파일 또는 디렉터리를 묶어 관리할 수 있다. <br> 윈도우 운영체제에서는 디렉터리를 폴더(folder)라고 부른다. |
| **경로<br>(Path)** | **개념:** 디렉터리 구조를 이용해 파일이나 폴더의 위치를 특정하는 정보<br><br>&nbsp;&nbsp;├── **절대 경로 (Absolute Path):** 루트 디렉터리부터 시작하는 고유한 전체 경로<br>&nbsp;&nbsp;│&nbsp;&nbsp;└── *예시:* `C:\Github\ComputerOrganizationAndDesign\Chapter 15 파일 시스템\chapter15.md`<br>&nbsp;&nbsp;│<br>&nbsp;&nbsp;└── **상대 경로 (Relative Path):** 현재 작업 디렉터리(Working Directory)를 기준으로 표현한 경로<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;└── *예시:* `.\Chapter 15 파일 시스템\chapter15.md` 또는 `../chapter15.md` |
| **파티셔닝(partitioning)** | 하드 디스크나 SSD처럼 용량이 큰 저장 장치를 하나 이상의 논리적인 여러 단위로 구획하는 작업 |
| **포매팅(formatting)** | 파일 시스템을 설정하여 어떤 방식으로 파일을 저장하고 관리할 것인지를 결정하고, 새로운 데이터를 쓸 수 있게 하는 작업 |
| **파일을 보조기억장치에 할당하는 방법** | • **연속 할당(contiguous allocation):** 보조기억장치 내 연속적인 블록에 파일을 할당하는 방식 <br> • **불연속 할당** <br>&nbsp;&nbsp;├── **연결 할당(linked allocation):** 각 블록 일부에 다음 블록의 주소를 저장하여 블록들을 연결 리스트 형태로 관리하는 방식<br>&nbsp;&nbsp;└── **색인 할당(indexed allocation):** 파일의 모든 블록 주소를 색인 블록에 모아 관리하는 방식. |
| **파일 시스템의 유형** | • **FAT(파일 할당 테이블; File Allocation Table) 파일 시스템:** FAT를 이용하는 연결 할당 기반의 파일 시스템 <br> • **유닉스 파일 시스템:** i-node(index-node)를 이용하는 색인 할당 기반의 파일 시스템 |
