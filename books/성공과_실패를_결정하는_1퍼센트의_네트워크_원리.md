### 2. 웹 서버의 IP주소를 DNS 서버에 조회한다

1. Socket 라이브러리가 IP주소를 찾는 기능을 제공한다.
2. 리졸버를 이용하여 DNS서버를 조회한다.

### 3. 전 세계의 DNS 서버가 연대한다

1. DNS 서버의 기본 동작<br>
조회 메시지에 포함된 정보<br>
(1) 이름 <br>
(2) 클래스<br>
(3) 타입<br><br>
DNS 서버는 서버에 등록된 도메인명과 IP 주소의 대응표를 조사하여 IP 주소를 회답한다.

2. 도메인의 계층<br>
DNS에서 취급하는 이름은 www.lab.cyber.co.kr처럼 점으로 구분되어 있는데, 이 점이 계층을 구분한다. 이는 'com사업부 cyber부 lab과의 www'라는 이름과 같다. 이처럼 하나의 부서에 해당하는 것을 도메인이라고 한다.

3. 담당 DNS 서버를 찾아 IP주소를 가져온다.<br>
com이나 kr이라는 최상위 도메인의 상위에 루트 도메인이라는 도메인이 있다. 클라이언트와 가장 가까이 있는 DNS 서버에 웹 서버에 관한 정보를 조회하고, 이름이 등록되어 있지 않으면 도메인의 계층을 취로부터 차례로 따라간다. 가장 가까운 DNS 서버에는 루트 도메인의 DNS서버가 등록되어 있으므로 루트 도메인의 DNS서버에 클라이언트로부터 받은 조회 메시지를 전송한다.

4. DNS 서버는 캐시 기능으로 빠르게 회답할 수 있다.<br> 
DNS서버는 한 번 조사한 이름을 캐시에 기록할 수 있는데, 조회한 이름에 해당하는 정보가 캐시에 있으면 그 정보를 회답하기 때문이다.

### 4. 프로토콜 스택에 메시지 송신을 의뢰한다

1. 데이터 송·수신 동작의 개요<br>
OS 내부의 프로토콜 스택에 메시지 송신 동작을 의뢰할 때는 Socket 라이브러리 프로그램 부품을 결정된 순번대로 호출한다.<br>
(1) 소켓을 만든다(소켓 작성 단계)<br>
(2) 서버측의 소켓에 파이프를 연결한다(접속 단계)<br>
(3) 데이터를 송·수신한다(송·수신 단계).<br>
(4) 파이프를 분리하고 소켓을 말소한다(연결 끊기 단계)

2. 소켓의 작성 단계<br>
소켓 라이브러리의 socket이라는 프로그램 부품만 호출하면 된다.<br>
애플리케이션은 '디스크립터'라는 번호표 같은 것으로, 소켓을 식별한다.

3. 파이프를 연결하는 접속 단계<br>
애플리케이션은 Socket 라이브러리의 connect라는 프로그램 부품을 호출하여 만든 소켓을 서버측의 소켓에 접속하도록 프로토콜 스택에 의뢰하는 동작을 실행한다.<br>
• 디스크립터: 애플리케이션이 소켓을 식별하는 것<br>
• IP 주소와 포트 번호: 클라이언트와 서버 간에 상대의 소켓을 식별하는 것

4. 메시지를 주고 받는 송·수신단계<br>
소켓에서 데이터를 보내면 상대측의 소켓에 데이터가 도착한다. 이를 위해 애플리케이션은 Socket라이브러리를 통해 프로토콜 스택에 디스크립터와 송신 데이터를 지정하고, write라는 프로그램 부품을 호출해서 프로토콜 스택이 송신 데이터를 서버에 송신한다. 그러면 서버는 수신 동작을 실행하여 받은 데이터의 내용을 조사하고 적절한 처리를 실행하여 응답 메시지를 반송한다.

5. 연결 끊기 단계에서 송·수신이 종료된다
브라우저가 데이터 수신을 완료하면 송·수신 동작은 끝난다. 그 후 Socket 라이브러리의 close라는 프로그램 부품을 호출하여 연결 끊기 단계로 들어가도록 의뢰한다. 그러면 소켓 사이를 연결한 파이프가 분리되고 소켓도 말소된다.

## <a id="ch02"></a>Chapter 02 TCP/IP의 데이터를 전기 신호로 만들어 보낸다 <sub>- 프로토콜 스택과 LAN 어댑터의 탐험</sub>

### 1. 소켓을 작성한다

#### (1) 프로토콜 스택의 내부구성

```text
┌── 애플리케이션
|   ├── 네트워크 애플리케이션(웹 브라우저, 메일러, 웹 서버, 메일 서버 등)
|   └── Socket 라이브러리(리졸버)
├── OS
|   └── 프로토콜 스택
|       ├── TCP 
|       ├── UDP
|       └── IP(패킷 운반, 경로 결정)
|           ├── ICMP
|           └── ARP
├── 드라이버 소프트웨어
|   └── LAN 드라이버(LAN 어댑터 제어)
└── 하드웨어
    └── LAN 어댑터: 케이블에 대해 신호를 송·수신하는 동작을 실행
```

• 브라우저나 메일 등의 일반적인 애플리케이션이 데이터를 송·수신할 경우에는 TCP<br>
• DNS서버에 대한 조회 등에서 짧은 제어용 데이터를 송·수신할 경우에는 UDP

#### (2) 소켓의 실체는 통신 제어용 제어 정보

프로토콜 스택은 소켓에 기록된 제어 정보를 참조하면서 움직인다.<br>

#### (3) Socket을 호출했을 때의 동작

1. socket을 호출하여 소켓을 만든다.<br>

- 소켓을 만들 때 한 개의 메모리 영역을 확보하고 초기 상태라는 것을 메모리 영역에 기록한다.
- 소켓이 만들어지면 소켓을 나타내는 디스크립터를 애플리케이션에 알려준다.
- 디스크립터를 받은 애플리케이션은 프로토콜스택에 데이터 송·수신 동작을 의뢰할 때 디스크립터를 통지한다.

### 2. 서버에 접속한다

#### 1. 접속의 의미

소켓을 만들면 애플리케이션(브라우저)은 connect를 호출한다. 그러면 프로토콜 스택은 자기쪽의 소켓을 서버측의 소켓에 접속한다.

#### 2. 맨 앞 부분에 제어 정보를 기록한 헤더를 배치한다

통신 동작에 이용하는 제어 정보는 다음의 두 종류이다.<br>
• 헤더에 기입되는 정보<br>
• 소켓(프로토콜 스택의 메모리 영역)에 기록되는 정보

#### 3. 접속 동작의 실체

접속 동작의 첫 걸음은 TCP 담당 부분에서 접속을 나타내는 제어 정보를 가록한 TCP헤더를 만드는 것이다. 그리고 TCP 헤더의 송신처와 수신처의 포트 번호로 접속하는 소켓을 지정한다.

### 3. 데이터를 송·수신한다

#### 1. 프로토콜 스택에 HTTP 리퀘스트 메시지를 넘긴다

• MTU: 패킷 한 개로 운반할 수 있는 디지털 데이터의 최대 길이. 이더넷에서는 보통 1,500바이트<br>
• MSS: 헤더를 제외하고 한 개의 패킷으로 운반할 수 있는 TCP의 데이터의 최대 길이

#### 2. 데이터가 클 때는 분할하여 보낸다

#### 3. ACK번호를 사용하여 패킷이 도착했는지 확인한다

TCP에는 송신한 패킷이 상대에게 올바르게 도착했는지 확인하고, 도착하지 않았으면 다시 송신하는 기능이 있으므로 패킷을 송신한 후에는 확인 동작으로 넘어간다.

시퀀스 번호를 통해 누락이 없는 것을 확인하면 수신측은 그 이전에 수신한 데이터와 합쳐서 데이터를 몇 번째 바이트까지 수신한 것인지 계산하고, 그 값을 TCP 헤더의 **ACK 번호**에 기록하여 송신측에 알려준다. 이 ACK 번호를 되돌려 주는 동작을 **수신 확인 응답**이라고 부르며, 송신측은 이것을 통해 상대가 어디까지 수신했는지 파악한다.

시퀀스 번호와 ACK 번호로 패킷이 수신측에 도착한 것을 확인한다.

#### 4. 패킷 평균 왕복 시간으로 ACK 번호의 대기 시간을 조정한다

ACK 번호가 돌아오는 시간을 기준으로 대기시간을 판단한다.

#### 5. 윈도우 제어 방식으로 효율적으로 ACK 번호를 관리한다

윈도우 제어는 한 개의 패킷을 보낸 후 ACK번호를 기다리지 않고 차례대로 연속해서 복수의 패킷을 보내는 방법이다. 그러면 ACK 번호가 돌아올 때까지의 시간이 낭비되지 않는다.

수신 가능한 데이터 양의 최대값을 윈도우 사이즈라고 부르며, TCP를 정밀조정하는 매개변수의 하나로 알려져 있다.

### 4. 서버에서 연결을 끊어 소켓을 말소한다

#### 1. 데이터 보내기를 완료했을 때 연결을 끊는다

1. 서버측의 애플리케이션이 먼저 Socket라이브러리의 close를 호출한다. 서버측의 프로토콜 스택이 TCP 헤더를 만들고 컨트롤 비트의 FIN에 1을 설정하고, IP 담당 부분에 의뢰하여 클라이언트에 송신해달라고 한다.
2. 클라이언트측의 프로토콜 스택은 FIN을 1로 설정한 패킷을 받은 사실을 알리기 위해 ACK 번호를 서버측에 반송한다.
3. 클라이언트측의 프로토콜 스택은 FIN 비트에 1을 설정한 TCP 헤더를 만들고 IP 담당 부분에 의뢰하여 서버에 송신한다.
4. 서버에서 ACK번호가 돌아오면 서버와의 대화가 끝난다.

### 5. IP와 이더넷의 패킷 송·수신 동작

#### 1. 패킷의 기본

패킷은 '헤더'와 '데이터'의 두 부분으로 구성된다.<br>
TCP/IP의 패킷: MAC 헤더(이더넷용 헤더) - IP 헤더(IP용 헤더) - TCP 헤더 - 데이터 조각<br>

#### 2. 패킷 송·수신 동작의 개요

IP 담당 부분은 다음 두 개의 헤더를 덧붙인다.

- MAC 헤더: 이더넷용 헤더, MAC 주소를 쓴다.
- IP 헤더: IP용 헤더, IP 주소를 쓴다.

IP가 패킷을 송·수신하는 동작은 제어 패킷이든지, 데이터의 패킷이든지 패킷의 역할에 상관 없이 모두 같다.

#### 3. 수신처 IP 주소를 기록한 IP 헤더를 만든다

IP 헤더의 수신처 IP 주소에는 통신 상대의 주소를 설정한다. <br>
송신처 IP 주소는 송신처가 되는 LAN 어댑터를 판단하여 주소를 설정한다.

#### 4. 이더넷용 MAC 헤더를 만든다

IP 담당 부분은 IP 헤더를 붙였으면 그 앞에 MAC 헤더를 붙인다. MAC 헤더는 이더넷에서 사용하는 헤더로서 수신처나 송신처의 MAC 주소 등이 기록되어 있다.

IP 담당 부분은 경로표의 'Gateway'항목의 값에서 패킷을 건네줄 상대를 판단한다.

#### 5. ARP로 수신처 라우터의 MAC 주소를 조사한다

MAC 주소를 조사할 때는 ARP를 사용한다.

#### 7. IP 패킷을 전기나 빛의 신호로 변환하여 송신한다

- LAN 어댑터에 기록된 MAC 주소는 LAN 드라이버가 MAC 회로에 설정한다.

#### 8. 패킷에 3개의 제어용 데이터를 추가한다

MAC 회로는 먼저 송신 패킷을 버퍼 메모리에서 추출하고 맨 앞에는 프리앰블과 스타트 프레임 딜리미터라는 두 개의 데이터를, 맨 끝에는 프레임 체크 시퀀스(FCS)를 부가한다.

#### 9. 허브를 향해 패킷을 송신한다

프리앰블, 스타트 프레임 딜리미터, FCS의 세 가지를 부가하면 케이블에 송출하는 패킷이 완성된다. 신호를 송신하는 동작에는 **리피터 허브**를 사용했을 때의 **반이중 모드**와 **스위칭 허브**를 사용한 **전이중 모드**의 두 가지가 있다.

## <a id="ch03"></a>Chapter 03 케이블의 앞은 LAN 기기였다 <sub>- 허브와 스위치, 라우터의 탐험</sub>

### 1. 케이블과 리피터, 허브 속을 신호가 흘러간다

#### 1. 하나하나의 패킷이 독립된 것으로 동작한다

중계 동작을 할 때 중계 장치는 데이터 부분을 보지 않고 패킷을 중계하므로 모든 캐팃은 아무 관련도 없는 별개의 것으로 간주하고 목적지를 향해 중계된다.

클라이언트 PC가 송신한 패킷이 리피터 허브, 스위칭 허브, 라우터를 경유하여 인터넷에 나간다.

#### 2. LAN 케이블은 신호를 약화시키지 않는 것이 핵심이다

LAN 어댑터의 PHY(MAU) 회로에서 전기 신호로 형태를 바꾼 패킷은 RJ-45 커넷터를 통해 **트위스트 페어 케이블(꼰 선쌍)** 에 들어간다.

#### 3. '꼼'은 잡음을 방지하기 위한 방법이다

LAN 케이블로 사용하는 트위스트 페어 케이블(꼰 선쌍)에는 잡음의 영향을 억제하는 대책이 마련되어 있는데, 이것이 '꼼'이다. '트위스트 페어(꼰 쌍)'라는 말은 두 가닥의 신호선을 한 조로 하여 마주 꼬았다는 데서 붙인 이름으로, 신호선을 마주 꼬아서 잡음을 막을 수 있다.

잡음의 원인은 케이블의 주위에서 발생하는 전자파이다.

#### 4. 리피터 허브는 연결되어 있는 전체 케이블에 신호를 송신한다

전체에 패킷의 신호를 뿌리고 수신처 MAC 주소에 해당하는 기기만 패킷을 수신한다는 원리를 그대로 실현한 것이 리피터 허브이므로 이더넷의 기본에 따라 신호를 뿌린다.

리피터 허브는 연결된 케이블 전부에 신호를 송신한다.

### 2. 스위칭 허브의 패킷 중계 동작

#### 1. 스위칭 허브는 주소 테이블로 중계한다

스위칭 허브의 포트에서 MAC 회로에는 MAC 주소가 할당되어 있지 않다.

스위칭 허브는 MAC 주소표에서 MAC 주소를 조사하고 해당하는 포트에서 신호를 송신한다.

#### 2. MAC 주소 테이블을 등록 및 갱신한다

#### 3. 예외적인 동작

스위칭 허브는 패킷을 수신한 포트와 송신하는 포트가 같을 경우 패킷을 중계하지 않고 폐기한다.

#### 4. 전이중 모드에서 송신과 수신을 동시에 실행한다

전이중 모드, 즉 송신과 수신을 동시에 실행할 수 있는 성질도 리피터 허브에 없는 스위칭 허브의 특징이다.

스위칭 허브의 전이중 모드는 송신과 수신을 동시에 실행한다.

#### 5. 최적의 전송 속도로 보내는 자동 조정

상대의 전송 속도를 검출하여 전송 속도를 자동으로 전환하는 기능을 자동 조정(auto negotiation)이라고 한다.

이더넷은 데이터가 흐르고 있지 않을 때는 링크 펄스라는 펄스형의 신호를 흘린다.

#### 6. 스위칭 허브는 복수의 중계 동작을 동시에 실행한다

스위칭 허브는 수신처 MAC 주소의 기기가 존재하는 포트 이외에는 송신 동작을 실행하지 않으므로 다른 포트는 빈 상태가 된다. 여기에서 별도의 패킷을 흘릴 수 있으며, 이렇게 해서 동시에 여러 개의 패킷을 중계할 수 있다.

### 3. 라우터의 패킷 중계 동작

#### 1. 라우터의 기본

라우터의 내부 구조는 **중계 부분**과 **포트부분**이라는 두 부분으로 구성되어 있다. 중계 부분이 패킷의 중계 대상을 판단하는 동작을 담당하고, 포트 부분이 패킷을 송·수신하는 동작을 담당한다.

라우터의 각 포트에는 MAC 주소와 IP 주소가 할당되어 있다.

#### 2. 경로표에 등록된 정보

라우터는 IP주소로 중계 대상을 판단한다. 라우터의 테이블은 **라우팅 테이블** 또는 **경로표**라고 부르며, 수신처(Destination), 넷마스크(Netmask), 게이트웨이(Gateway), 인터페이스(Interface), 메트릭(Metric)과 같은 정보를 등록한다.

라우터는 호스트 번호를 무시하고 네트워크 번호 부분만 조사한다.

**주소 집약**이라는 개념을 이용하면 몇 개의 서브넷을 모아서 한 개의 서브넷으로 간주한 후 묶은 서브넷을 경로표에 등록할 수 있다.

라우터의 경로표에서 '넷마스크' 항목은 경로표의 수신처와 패킷의 수신처 주소를 대조할 때 비트 수를 나타낸다.

#### 3. 라우터의 패킷 수신 동작

라우터의 포트에는 MAC 주소가 할당되어 있으며, 라우터는 자신의 주소에 해당하는 패킷만 수신하고 해당하지 않는 패킷을 폐기한다.

#### 4. 경로표를 검색하여 출력 포트를 발견한다

라우터에서 중계하는 패킷의 수신처 MAC 주소에는 라우터의 포트에 할당된 MAC 주소가 기록되어 있다.

#### 5. 해당하는 경로가 없는 경우에 선택하는 기본 경로

라우터의 경로표에서 '넷마스크'항목의 0.0.0.0인 행은 '기본 경로'를 나타난다.

#### 6. 패킷은 유효기간이 있다  

라우터를 경유할 때마다 TTL(Time To Live, 생존 시간)이라는 IP헤더의 필드 값을 1씩 줄이다가 이 숫자가 0이 되면 패킷의 생존기간이 만료되는 것으로 간주하여 패킷을 폐기한다.

#### 7. 큰 패킷은 조각 나누기 기능으로 분할한다

중계하는 패킷의 크기가 출력측의 패킷 최대 길이를 초과하면 그대로는 패킷을 송신할 수 없다. 이 경우에는 IP 프로토콜에 규정된 조각 나누기(fragmentation)이라는 방법을 사용하여 패킷을 분할하고, 패킷의 길이를 짧게 만든 후 중계한다.

#### 8. 라우터의 송신 동작은 컴퓨터와 같다

라우터가 다음에 건네줄 상대를 판단하는 방법

- 경로표의 '게이트웨이' 항목에 IP 주소가 쓰여있으면 IP 주소가 건네줄 상대
- 경로표의 '게이트웨이' 항목이 공란이면 IP 헤더의 수신처 IP 주소가 건네줄 상대

라우터도 ARP를 사용하여 다음에 건네줄 상대의 MAC주소를 조사한다.

#### 9. 라우터와 스위칭 허브의 관계

컴퓨터가 패킷을 송신할 때 또는 라우터가 패킷을 중계할 때 맨 앞에 MAC 헤더를 부가한다. MAC 헤더를 부가하여 패킷을 송신한다는 것은 이더넷의 패킷의 데이터 부분에 IP의 패킷을 넣고 이더넷의 원리로 다음 라우터까지 운반한다는 것이다. 즉 라우터는 패킷을 운반하는 일을 스위칭 허브에 의뢰한다.

통신 상대까지 패킷을 전달하는 전체의 동작은 IP(라우터)가 담당하고, 이 동작을 할 때 다음 라우터까지 패킷을 운반하는 부분은 이더넷(스위칭 허브)이 담당한다.

### 4. 라우터의 부가 기능

#### 1. 주소 변환으로 IP 주소를 효율적으로 이용한다

특정 주소를 사내용으로 사용한다는 규칙에 기초한 사내용 주소는 **프라이핏 주소(private address)** 로, 고유한 주소는 **글로벌 주소(global address)** 로 부른다.

프라이빗 주소로 사내에서 사용하는 것은 아래의 범위로 한정한다.

- 10.0.0.0 ~ 10.255.255.255
- 172.16.0.0 ~ 172.31.255.255
- 192.168.0.0 ~ 192.168.255.255

#### 2. 주소 변환의 기본 동작

주소 변환의 구조는 패킷을 중계할 때 IP 헤더에 기재된 IP 주소와 포트 번호를 바꿔쓰는 것이다.

#### 3. 포트 번호를 바꿔쓰는 이유

클라이언트측의 포트 번호는 원래 비어있는 것이어서 무작위로 선택하여 사용할 뿐이므로 포트 번호를 바꿔써도 문제가 발생하지 않는다. 그래서 포트 번호를 글로벌 주소와 한 세트로 하여 프라이비트 주소에 대응시키면 한 개의 글로벌 주소를 수만 개의 프라이비트 주소에 대응시킬 수 있는데, 이렇게 하는 쪽이 글로벌 주소의 이용 효율이 높아진다.

#### 4. 인터넷에서 회사로 액세스한다

인터넷에서 사내로 패킷을 중계할 때는 대응표에 등록되어 있지 않으면 중계할 수 없다. 인터넷에서 사내에 액세스 할 수 없는 이유는 대응표에 등록되어 있지 않기 때문이므로 사전에 수동으로 대응표에 등록해두면 된다.

#### 5. 라우터의 패킷 필터링 기능

패킷 필터링 기능은 패킷을 중계할 때 MAC 헤더, IP 헤더, TCP 헤더에 기록되어 있는 내용을 조사하여 그것이 사전에 설정한 조건에 합치되면 패킷을 중계하거나 폐기하는 동작을 실행하는 것이다.

## <a id="ch04"></a>Chapter 04 액세스 회선을 통해 인터넷의 내부로! <sub>- 액세스 회선과 프로바이더의 탐험</sub>

### 1. ADSL 기술을 이용한 액세스 회선의 구조와 동작

#### 1. 인터넷의 기본은 가정이나 회사의 LAN과 같다

거리의 차이와 경로 정보의 등록 방법의 차이가 인터넷과 회사나 가정의 LAN과 차이점이다.

#### 2. 사용자와 인터넷을 연결하는 액세스 회선

액세스 회선은 인터넷과 가정이나 회사의 LAN을 연결하는 통신 회선을 말한다.

#### 3. ADSL모델에서 패킷을 셀로 분할한다

인터넷 접속용 라우터는 MAC 헤더, PPPoE 헤더, PPP 헤더의 세 가지를 붙이고 ADSL 모뎀에 패킷을 보낸다(PPPoe의 경우)

ADSL 모뎀은 패킷을 셀로 분할하고, 전기 신호로 바꾸어 스플리터에 송신한다.

#### 4. ADSL은 변조 방식으로 셀을 신호화한다

ADSL 모뎀은 완만한 파형(정현파)을 합성한 신호에 0과 1의 비트 값을 대응시키는 기술을 사용하는데, 이 기술을 **변조 기술**이라고 한다. ADSL은 진폭 변조(ASK)라는 방식과 위상 변조(PSK)라는 방식을 결합한 직교 진폭 변조(QAM)라는 방식을 사용한다.

진폭 변조 방식은 신호의 세기, 즉 신호의 진폭의 크기에 0과 1을 대응시키는 방법이다. 위상 변조는 신호의 위상에 0과 1을 대응시키는 방법이다. 신호의 진폭과 위상에 각각 1비트를 대응시키고, 한 개의 파에 2비트분의 데이터를 대응시키는 것처럼 한 개의 파에 대응시키는 비트 수를 늘려 속도를 높인 것이 직교 진폭 변조 방식이다.

#### 5. ADSL은 파를 많이 사용하여 고속화를 실현한다

ADSL은 여러 주파수의 파를 합성한 것을 신호로 사용하는 것도 가능하다. 이렇게 하면 대응시키는 비트 수는 사용하는 파의 수를 곱한 것만큼 증가한다. ADSL은 이 성질을 사용하여 다수의 파에 비트 값을 대응시켜서 고속화를 실현한다.

ADSL은 모델의 전원을 공급할 때 시험 신호를 보내고, 이 수신 상태에 따라 파의 수나 비트 수를 판단하는 것을 **트레이닝**이라고 한다.

#### 6. 스플리터의 역할

- 사용자측에서 신호를 전화 회선에 송출할 때: 스플리터는 특별히 하는 일이 없다.
- 전회 회선에서 신호가 들어올 때: 전화와 ADSL의 신호를 나누는 역할을 한다.

#### 7. 전화국까지의 여정

```text
[실내 ADSL 모뎀]
       │
       ▼
   [스플리터]
       │
       ▼
 [모듈형 커넥터]
       │
       ├── [건물]    ──> [중간 배선반 (IDF)] ──> [주 배선반 (MDF)] ───┐
       │                                                            │
       └── [단독주택] ──> [옥내 배선] ─────────> [보안기 (낙뢰 방지)] ─┤
                                                                    │
                                                                    ▼
                                                           [전주의 전화 케이블]
                                                                    │
                                                                    ▼
                                                      [지하 전화 케이블(동도; 洞道)]
                                                                    │
                                                                    ▼
                                                                 [전화국]
```

#### 8. 잡음의 영향

케이블의 외부에서 들어오는 잡음이나 케이블의 내부에서 발생하는 잡음(크로스토크)의 영향을 받으면 신호가 변형된다.<br>
• 트위스트 페어 케이블: 사각형 신호가 한 개이므로 사각형 신호가 변형되면 신호에서 디지털 데이터를 읽을 수 없게 되어 오류가 발생함<br>
• ADSL의 신호: 다수의 주파수로 나뉘어져 잡음과 주파수가 겹치는 신호만 영향을 받아서 사용할 수 있는 신호의 수가 감소하여 속도가 저하됨.

#### 9. DSLAM을 통과하여 BAS에 도달한다

DSLAM은 ATM 인터페이스를 가지고 있고 패킷을 분할한 셀 형태 그대로 후방의 라우터와 주고 받는다. 

BAS(Broadband Access Server)에 있는 ATM 인터페이스가 셀을 수신한다. ATM 인터페이스는 수신한 셀을 원래의 패킷으로 복원하는 기능이 있다. 그러면 수신한 패킷의 맨 앞 부분에 있는 MAC 헤더와 PPPoE헤더를 버리고 PPP 헤더 이후의 부분을 추출한다. 즉, BAS는 ATM 셀을 패킷으로 복원하여 인터넷의 내부에 중계한다.

### 2. 광섬유를 이용한 액세스 회선(FTTH)

#### 1. 광섬유의 기본

광섬유는 이중 구조의 가는 섬유질의 투명한 재질로 만들어져 있으며, 안쪽에 있는 코어 부분 속에 광신호를 흘려서 디지털 데이터를 전달한다.

#### 2. 싱글모드와 멀티모드의 차이

| 구분 | 싱글모드 | 멀티모드 |
| :-- | :-- | :-- |
| **코어의 직경** | 코어의 직경이 가는 것(8~10µm) | 코어의 직경이 굵은 것(50µm 또는 62.5µm) |
| **위상이 같은 각도의 개수** | 한 개 | 여러 개 |
| **광원이나 수광 소자의 성능** | 코어 속을 진행하는 빛이 한 개 밖에 없으므로 빛의 양이 적은 만큼 광원이나 수광 소자의 성능이 높아져야 한다. 신호의 변형이 적다. | 코어 속에 복수의 빛이 흐르고 잇으므로 빛의 양이 많은 만큼 광원이나 수광 소자의 성능이 비교작 낮은 것이라도 상관 없기 때문에 광원이나 수광 소자의 가격을 줄일 수 있다. |
| **신호 변형 여부** | 코어를 진행하는 빛은 한 개뿐이므로 거리가 달라서 도착 시간에 차이가 생기는 현상이 일어나지 않으므로 케이블 길이가 길어져도 신호의 변형이 없다. | 반사각이 다른 몇 개의 빛이 코어 속을 진행하므로 신호가 도착하는 시간이 일정하지 않아 신호의 폭이 넓어지면서 신호가 변형된다. |
| **사용 용도** | 멀리 떨어진 장소에 있는 건물 사이를 연결할 때 사용 | 한 건물 안을 연결하는 용도 |

#### 4. 광섬유를 분기시켜서 비용을 절감한다

ADSL 대신 광섬유를 사용하여 사용자측의 인터넷 접속용 라우터와 인터넷 측의 BAS를 접속하는 것이 FTTH 액세스 회선이다.

FTTH 액세스 회선의 형태

1. 한 개의 광섬유로 사용자측과 가장 가까운 전화국측을 접속하는 유형<br>
한 개의 광섬유를 사용하여 파장이 서로 다른 복수의 광신호를 흘리는 것을 **파장 다중**이라고 한다.
2. 사용자 부근의 전주에 **광스플리터**라는 분기 장치를 설치하고, 광스플리터에서 광섬유를 분기시켜서 복수의 사용자를 연결하는 유형

### 3. 액세스 회선으로 이용하는 PPP와 터널링

#### 1. 본인 확인과 설정 정보를 통지한다

인터넷 = 다수의 라우터 연결 => 액세스 회선을 라우터에 연결하는 것이 원칙<br>
액세스 회선이 ADSL이나 FTTH로 진화 => 라우터는 BAS로 진화<br>
BAS는 본인 확인과 설정값 통지 기능이 진화했다.

BAS는 로그인 창구 역할을 하기 위해 PPPoE라는 구조를 사용한다.

#### 2. 이더넷에서 PPP 메시지를 주고 받는 PPPoE

PPPoE는 PPP 메시지를 이더넷의 패킷에 넣어 주고 받는다.

#### 3. 터널링 기능에 의해 프로바이더에 패킷을 전달한다.

한 쪽의 터널링 입구에서 헤더를 포함한 패킷 전체를 넣으면, 이것이 헤더를 포함하여 그대로의 모습으로 반대쪽 출입구에 도달하는 기능이 터널링이다. 네트워크 안에 터널이 만들어지고, 그 속을 패킷이 통과하는 식이다.

#### 4. 액세스 회선 전체의 동작

인터넷 접속용 라우터는 PPPoE의 Discovery라는 구조에 따라 BAS의 MAC 주소를 찾는다.

BAS에서 보낸 TCP/IP 설정값은 인터넷 접속용 라우터의 BAS측 포트에 설정되고, 이렇게 해서 인터넷 접속용 라우터의 준비는 완료된다.

BAS는 인터넷 접속용 라우터에서 보내온 패킷을 받아 MAC 헤더와 PPPoE 헤더를 제거한 후 터널링의 원리를 사용하여 프로바이더의 라우터를 향해 송신한다.

#### 5. IP 어드레스를 할당하지 않는 언넘버드

1 대 1 형태로 접속된 포트에 IP 주소를 할당하지 않아도 좋다는 특례가 있는데, 이것을 언넘버드(unnumbered)라고 한다.

#### 6. 인터넷 접속용 라우터에서 프라이비트 주소를 글로벌 주소로 변환한다

#### 7. PPPoE 이외의 방식

- PPPoA: MAC 헤더와 PPPoE 헤더를 붙이지 않고 패킷을 그대로 저장하는 방식
- DHCP 방식: PPP를 사용하지 않고 이더넷의 패킷을 그대로 ADSL 신호로 변환하여 DSLAM에 송신하는 방식

### 4. 프로바이더의 내부

#### 1. POP와 NOC

액세스 회선을 통과한 패킷은 프로바이더의 POP에 설치된 라우터에 도착한다. NOC(Network Operation Center)는 프로바이더의 핵심이 되는 설비로서 POP에서 들어온 패킷이 모여든다. 패킷을 중계하는 기본 동작은 모든 라우터에서 차이가 없기 때문에 NOC와 POP는 엄밀하게 구분할 수 없고, POP의 규모가 큰 것이 NOC라고 생각하면 된다.

#### 2. 건물 밖은 통신 회선 등으로 접속한다

광섬유를 가지고 있지 않은 프로바이더는 통신 회선을 사용하여 멀리 떨어진 장소에 있는 NOC나 POP를 연결한다.

### 5. 프로바이더를 경유하여 흐르는 패킷

#### 1. 프로바이더끼리의 접속

- 웹 서버와 클라이언트가 같은 프로바이더에 접속되어 있는 경우: 프로바이더의 라우터에는 라우터끼리 경로 정보를 교환하고, 경로 정보를 경로표에 자동으로 등록한다.
- 웹 서버와 클라이언트가 다른 프로바이더에 접속되어 있는 경우: 경로표에 등록되어 있는 경우 경로표를 찾으면 중계 대상이 발견되므로 중계 대상에 패킷을 보내면 된다.

#### 2. 프로바이더끼리 경로 정보 교환하기

접속 상대가 경로 정보를 가르쳐주면 그곳에 어떤 네트워크가 있는지 알게 된다. 상대가 경로 정보를 가르쳐주면 이쪽에서도 같은 방법으로 경로 정보를 상대에게 통지한다. 그러면 상대측에서 이쪽의 네트워크로 보낼 패킷이 흘러온다. 이 경로 정보 교환 구조는 BGP(Border Gateway Protocol)이라고 한다.

경로 정보의 내용에 따른 경로 정보 교환의 유형

- 인터넷의 경로를 전부 상대에게 통지하는 것: 트랜지트(transit)
- 두 프로바이더가 각각의 네트워크에 관한 경로 정보만 상대에게 통지하는 것: 비트랜지트 또는 피어(peer)

#### 3. 사내 네트워크에서 자동 등록하기

#### 4. IX의 필요성

프로바이더끼리 접속하는 방법은 프로바이더끼리 1 대 1 형태로 접속하는 것이 기본이다. 그러나 프로바이더끼리 1 대 1로 접속하는 방법밖에 없으면 모든 프로바이더와 통신 회선을 연결해야 한다. 이러한 상황에서 중심이 되는 설비인 IX를 설치하고, IX를 경유하여 접속하는 방법을 선택하면 통신 회선의 수를 역제할 수 있다.

#### 5. IX에서 프로바이더끼리 접속하는 모습

IX의 중심에는 고속 LAN의 인터페이스를 다수 장착한 레이어 2 스위치가 있다. 레이어 2 스위치의 기본 동작은 스위칭 허브와 같으므로 고속으로 거대한 스위칭 허브가 IX의 핵심이 되었다.

IX에 프로바이더의 라우터를 연결하는 방법

- IX와 같은 건물에 NOC를 설치한 프로바이더가 선택하는 방법: NOC에서 광섬유 케이블을 가설하여 IX의 스위치에 접속
- 데이터 센터 등 패킷의 흐름이 집중되는 장소에 IX의 목적지가 되는 스위치를 설치하고, 여기에 프로바이더의 라우터를 가지고 연결

### 3. 복수 서버에 리퀘스트를 분배한 서버의 부하 분산

#### 1. 처리 능력이 부족하면 복수 서버로 부하 분산된다

복수의 서버를 사용하여 처리를 분담하는 방법으로 서버 한 대당 처리량을 줄이는 처리 방법을 **분산 처리**라고 한다.

서버에 액세스할 때 DNS 서버에 조회하여 IP 주소를 조사하는데, DNS 서버에 같은 이름으로 여러 대의 웹 서버를 등록해 놓으면 DNS 서버는 조회가 있을 때맏 차례대로 IP 주소를 되돌려준다. 1주기를 순환하고는 원래대로 돌아가는데 이 방법을 **라운드 로빈**이라고 한다.

```text
www.lab.cyber.co.kr이라는 서버명에 대해 
192.0.2.60, 192.0.2.70, 192.0.2.80이라는 3개의 IP 주소를 대응시킨다고 가정했을 때
최초의 조회에는 
192.0.2.60, 192.0.2.70, 192.0.2.80이라고 회답하고
다음 조회에는 192.0.2.70, 192.0.2.80, 192.0.2.60이라고 차례로 바꿔서 회답한 후
192.0.2.80, 192.0.2.60, 192.0.2.70을 회답하는 식이다.
```

#### 2. 부하 분산 장치를 이용해 복수의 웹 서버로 분할된다

라운드 로비에서 차례로 웹 서버를 분배하면 복수의 페이지에 걸쳐 대화하는 경우, 웹 서버가 변하면 대화가 도중에 끊기는 문제를 해결하기 위해 **부하 분산 장치** 또는 **로드 밸런서** 등으로 부르는 기기가 고안되었다.

어느 웹 서버에 리퀘스트를 전송해야 할 지 판단하는 방법

- 복수 페이지에 걸쳐있지 않은 단순한 액세스인 경우<br>웹 서버의 부하 상태가 판단 근거가 된다.
- 대화가 복수 페이지에 걸쳐 있는 경우<br>웹 서버의 부하에 관계 없이 이전의 리퀘스트와 같은 웹 서버에 전송해야 한다.

### 4. 캐시 서버를 이용한 서버의 부하 분산

#### 1. 캐시 서버의 이용

캐시 서버는 **프록시** 구조를 사용하여 데이터를 캐시에 저장하는 서버이다.

#### 2. 캐시 서버는 갱신일로 콘텐츠를 관리한다

#### 3. 프록시의 원점은 포워드 프록시이다

캐시서버에서 이용하는 프록시 구조는 원래 클라이언트측에 두는 방법에서 시작되었다. 이 유형이 프록시의 원형으로, **포워드 프록시**라고 한다. 포워드 프록시를 사용할 경우 보통 브라우저의 설정 화면에 준비되있는 **프록시 서버**라는 항목에 포워드 프록시의 IP 주소를 설정한다.

#### 4. 포워드 프록시를 개량한 리버스 프록시

리퀘스트 메시지의 URI에 쓰여있는 디렉토리명과 전송 대상의 웹 서버를 대응시켜서 URI 부분에 http://... 라고 쓰여있지 않은 보통의 리퀘스트 메시지를 전송할 수 있도록 했다. 이것이 서버측에 설치하는 캐시 서버에 채택하고 있는 방식으로, **리버스 프록시**라고 부른다.

#### 5. 트랜스패어런트 프록시

리퀘스트 메시지에서 패킷의 헤더를 조사하는 방법이 있다. 패킷의 맨 앞에 있는 IP 헤더에는 수신처 IP 주소가 기록되어 있으므로 이것을 조사하면 액세스 대상 웹 서버가 어디에 있는지 알 수 있는데, 이 방법을 **트랜스페어런트 프록시**라고 부른다.

### 5. 콘텐츠 배포 서비스

#### 1. 콘텐츠 배포 서비스를 이용한 부하 분산

캐시 서버를 설치하고 캐시 서버를 웹 서버 운영자에게 대출하는 서비스를 콘텐츠 배포 서비스(CDS)라고 하며, 이 서비스를 제공하는 사업자를 CDSP라고 한다. CDSP는 중요한 프로바이더와 계약하고 그곳에 다수의 캐시 서버를 설치한다.

#### 2. 가장 가까운 캐시 서버의 관점

콘텐츠 배포 서비스를 사용하는 경우 인터넷 전체에 설치된 다수의 캐시 서버를  이용하므로, 다수가 있는 캐시 서버 중에서 가장 가까운 캐시 서버를 찾아내고, 클라이언트가 여기에 액세스하도록 중재하는 구조가 필요하다.

#### 3. 리피터용 서버로 액세스 대상을 분배한다

가장 가까운 캐시 서버에 액세스 하는 방법으로 다른 웹 서버에 액세스하도록 처리하는 **리다이렉트(redirect)** 방식이 있다.

#### 4. 캐시 내용의 갱신 방법에서 성능의 차이가 난다

## <a id="ch06"></a>Chapter 06 웹 서버에 도착하여 응답 데이터가 웹 브라우저로 돌아간다 <sub>- 불과 몇 초인 '긴 여행'의 끝</sub>

### 1. 서버의 개요

#### 1. 클라이언트와 서버의 차이점

**공통점:** 네트워크 제어 구조(LAN 어댑터, OS 프로토콜 스택, Socket 라이브러리)의 기본 기능과 패킷 송수신 원리는 동일함.

| 구분 | 클라이언트 | 서버 |
| :-- | :-- | :-- |
| **종류** | 개인용 PC/모바일 기기 위주 | 용도와 처리량에 따라 다양한 고성능 하드웨어 존재 |
| **사용하는 방법** | 필요할 때 능동적으로 접속 동작 수행 (Connect) | 상시 대기 상태로 클라이언트 접속을 기다림 (Listen/Accept) |
| **대화 방식** | 한 번에 하나의 상대(서버)와 주로 통신 | 멀티프로세스/멀티스레드로 동시에 다수의 클라이언트와 대화 |

#### 2. 서버 애플리케이션 구조

서버는 동시에 복수의 클라이언트와 통신 동작을 실행하지만, 하나의 프로그램으로 여러 클라이언트들의 상대를 처리하기는 어렵다. 그래서 클라이언트가 접속할 때마다 새로 서버 프로그램을 작동하여 서버 애플리케이션이 클라이언트와 1 대 1로 대화하는 방법을 선택하는 것이 일반적이다. 서버 OS는 멀티태스크 또는 멀티스레드라는 기능에 의해 다수의 프로그램을 동시에 함께 작동할 수 있다.

#### 3. 서버측의 소켓과 포트 번호

클라이언트에서 접속 동작을 실행할 때 서버측의 소켓에 할당한 포트 번호를 지정하는데, 웹 서버의 경우 80번이다.

소켓을 식별하기 위해 디스크립터를 사용하는 이유

- 접속 대기의 소켓에는 클라리언트측의 IP주소와 포트 번호가 기록되어 있지 않기 때문이다.
- 디스크립터라는 한 개의 정보로 식별하는 쪽이 간단하기 때문이다.

### 2. 서버의 수신 동작

#### 1. LAN 어댑터에서 수신 신호를 디지털 데이터로 변환한다

LAN 어댑터의 MAC 부분이 패킷을 신호로부터 디지털 데이터로 되돌리고 FCS를 점검한 후 버퍼 메모리에 저장한다. 인터럽트를 사용해서 LAN 어댑터에서 CPU로 패킷의 도착을 알린다. LAN 드라이버가 MAC 헤더로부터 프로토콜을 판단하여 프로토콜 스택에 패킷을 건네준다.

#### 2. IP 담당 부분의 수신 동작

프로토콜 스택의 IP 담당 부분은 IP 헤더를 점검하고 (1) 자신을 대상으로 한 것인지 판단한 후 (2) 조각 나누기에 의한 패킷의 분할이 있는지 조사하고 (3) TCP 담당 부분 또는 UDP 담당 부분에 패킷을 건네준다.

#### 3. TCP 담당 부분이 접속 패킷을 수신했을 때의 동작

패킷이 접속 동작의 패킷인 경우 TCP 담당 부분은 (1) TCP 헤더의 SYN의 컨트롤 비트를 확인하고 (2) 수신처 포트 번호를 조사한 후 (3) 해당하는 접속 대기 소켓을 복사하여 새 소켓을 작성하고 (4) 송신처의 IP 주소나 포트 번호 등을 기록한다.

#### 4. TCP 담당 부분이 데이터 패킷을 수신했을 때의 동작

데이터의 패킷을 수신한 경우 TCP 담당 부분은 (1) 도착한 패킷의 송신처 IP 주소, 송신처 포트 번호, 수신처 IP 주소, 수신처 포트 번호로부터 해당하는 소켓을 판단하고 (2) 데이터의 조각을 연결해서 수신 버퍼에 보관한 후 (3) 클라이언트에게 ACK를 되돌려 준다.

#### 5. TCP 담당 부분의 연결 끊기 동작

TCP 프로토콜의 규칙에 따르면 연결 끊기 동작은 클라이언트와 서버 중 어느 쪽이 먼저 실행해도 상관없다. 서버측에서 애플리케이션이 Socket 라이브러리의 close를 호출하고 TCP 담당 부분이 FIN이라는 컨트롤 비트에 1을 설정한 TCP 헤더를 만든 후 IP 담당 부분에 의뢰하여 클라이언트에 보낸다. 이것이 클라이언트에 도착하면 클라이언트는 ACK 번호를 반송한다. 클라이언트가 close를 계속 호출하고, FIN을 1로 한 TCP 헤더를 서버에 보낸 후 서버가 ACK 번호를 반송하면 연결 끊기 동작은 끝난다.

### 3. 웹 서버 소프트웨어가 리퀘스트 메시지의 의미를 해석하여 요구에 응한다

#### 1. 조회의 URI를 실제 파일명으로 변환한다

#### 2. CGI 프로그램을 작동하는 경우

웹 서버에서 프로그램을 작동시키는 경우 프로그램에서 처리하는 데이터를 HTTP의 리퀘스트 메시지 안에 넣어 브라우저에서 웹 서버로 보내는 것이 일반적이다. 웹 서버는 먼저 URI의 부분에 쓰여있는 파일명을 조사하여 이것이 프로그램인지 판단한다. 파일이 프로그램인 것을 알고 있으면 웹 서버는 이 프로그램을 작동시키도록 OS에 의뢰한다. 그리고 리퀘스트 메시지에서 데이터를 추출하여 작동시킨 프로그램에 건네준다. 그러면 작동 시킨 프로그램이 받은 데이터를 처리하여 무언가의 출력 데이터를 웹 서버에 되돌려 준다. 웹 서버는 출력데이터를 그대로 응답 메시지로 클라이언트에 반송한다.

#### 3. 웹 서버로 수행하는 액세스 제어

조건에 따라 액세스 동작 여부를 설정하는 기능을 **액세스 제어**라고 한다. 웹 서버에서 설정하는 조건은 클라이언트의 주소, 클라이언트의 도메인명, 사용자명과 패스워드가 있다.

#### 4. 응답 메시지를 되돌려 보낸다

웹 서버가 Socket 라이브러리의 write를 호출하여 응답 메시지를 프로토콜 스택에 건네준다. 어느 소켓을 사용하여 통신하고 있는지를 나타내는 디스크립터를 통지하여 지정한 상대를 프로토콜 스택에 알려주어야 한다. 그러면 프로토콜 스택은 데이터를 한 개의 패킷에 들어가는 길이로 분할하고 헤더를 붙여서 패킷을 송출한다. 이 패킷은 스위치나 라우터를 경유하여 인터넷 속을 통해 최종적으로 클라이언트에게 도착한다.

### 4. 웹 브라우저가 응답 메시지를 받아 화면에 표시한다

#### 1. 응답 데이터의 형식을 보고 본질을 판단한다

응답 메시지의 맨 앞 부분에 있는 'Content-Type'이라는 헤더 파일의 값으로 데이터의 종류를 판단하는 것이 원칙이다.

```text
Content-Type: text/html
```

/의 왼쪽 부분은 '주 타입'이라 하고, 이것을 통해서 데이터 종류의 대부분을 나타낸다. 그리고 오른쪽의 '서브 타입'이라는 부분에 실제 데이터의 종류를 나타낸다.

#### 2. 브라우저 화면에 웹 페이지를 표시하여 액세스를 완료한다

데이터의 종류에 따라 화면 표시의 프로그램을 호출하여 데이터를 표시하면 된다. HTML 문서, 일반 텍스트, 화상이라는 기본적인 데이터는 브라우저 자체가 화면 표시 기능을 가지고 있으므로 브라우저가 자체에서 화면 표시 동작을 실행한다.

| **DNS 서버** | 웹 서버의 이름에서 IP 주소를 조사하기 위해 서용하는 서버 |
| **수신 버퍼** | 수신한 응답 메시지를 저장하기 위한 메모리 영역 |
| **패킷** | 네트워크에서 데이터는 수십 바이트에서 수천 바이트 정도의 작은 덩어리로 분할되어 운반된다. 이렇게 분할된 데이터의 덩어리를 패킷이라고 한다. |
| **ICMP** | 패킷을 운반할 때 발생하는 오류를 통지하거나 제어용 메시지를 통지할 때 사용 |
| **ARP(Address Resolution Protocol)** | IP 주소에 대응하는 이더넷의 MAC 주소를 조사할 때 사용한다. |
| **PID** | Process ID의 약자. 각 프로그램을 식별하기 위해 OS가 할당하는 번호. 작업관리자로 프로그램을 확인할 수 있다. |
| **시퀀스 번호** | TCP에서 데이터를 조각으로 분할할 때 조각이 통신 개시부터 따져서 몇 번째 바이트에 해당하는지를 세어서 TCP 헤더에 기록한 값 |
| **넷마스크** | IP 주소의 네트워크 번호와 호스트 번호의 경계를 결정하는 값. |
| **리피터 허브** | 이더넷(10BASE-T/100BASE-TX)의 허브. 구형의 신호를 증폭하여 중계하는 형태의 허브와 스위칭 허브를 구별하여 말할 때 전자를 '리피터 허브' 또는 '셰이드 허브', '공유 허브'라고 한다. |
| **FCS(Frame Check Sequence)** | 오류 검출용 데이터 |
| **재밍 신호** | 이더넷에서 충돌이 발생한 경우에 이것을 알리기 위해 흘리는 특수한 신호. '잼 신호'라고도 한다. |
| **PnP(Plug and Play)** | 확장 보드나 주변기기 등을 자동 설정하는 기능 |
| **프래그먼트 오프셋(fragment offset)** | 피킷이 원래 어느 위치에 있었는지를 나타내는 정보가 들어있다. |
| **리어셈블링(reassembling)** | 분할된 패킷이 전부 도착하기를 기다렸다가 패킷을 원래의 모습으로 되돌리는 동작 |
| **PHY(MAU)** | 이더넷에는 다수의 파생 방식이 있고, 파생 방식에 따라 신호 송·수신 회로의 호칭이 다르다. 현재의 100메가비트/초 이상의 이더넷은 'PHY(Physical Layer Device)'라고 부르는데, 이전의 저속 방식 중에는 MAU(Medium Attachment Unit)'라고 부르는 것도 있다. |
| **크로스 토크(crosstalk)** | 케이블 안의 인접한 신호선에 신호라는 전류가 흐르므로 전류에 의해 주위에 전자파가 생기면 다른 신호선에 대한 잡음에 의한 영향을 의미. |
| **브로드캐스트 주소** | 주소를 수신처 주소로 지정하여 패킷을 보내면 네트워크에 접속된 모든 기기에 패킷이 도착한다는 특별한 주소이다. LAN에 사용하는 MAC 주소는 FF:FF:FF:FF:FF:FF가 되고 IP 주소는 255.255.255.255가 브로드캐스트 주소가 된다. |
| **ICMP(Internet Control Message Protocol)** | 패킷을 운반할 때 발생하는 오류를 통지하거나 제어용 메시지를 보낼 때 이용한다. |
| **PPPoE(PPP over Ethernet)** | ADSL이나 FTTH라는 광대역 회선을 제어하는 방식 중 하나 |
| **ADSL(Asymmetric Digital Subscriber)** | 전주에 부설된 전화용 금속제 케이블을 이용하여 고속으로 통신하는 기술의 일종으로, 사용자로부터 인터넷으로 향하는 상향(업로드)과 인터넷에서 사용자를 향하는 하향(다운로드)의 통신 속도가 서로 다른 것을 가리킨다. |
| **BAS(Broadband Access Server)** | 라우터의 일종 |
| **PPP(Point-to-Point Protocol)** | 전화선이나 ISDN 등의 통신 회선을 사용하여 통신할 때 사용하는 구조이다. 본인 확인, 설정값 통지, 데이터 압충, 암호화 등 다양한 기능을 조합하여 사용할 수 있다. |
| **DSLAM(DSL Access Multiplexer)** | 전화국용 ADSL 집합 모뎀을 하나의 케이스에 넣은 기기 |
| **크로스토크** | 신호선에서 전자파가 누설되어 잡음이 되면서 케이블에 근접한 신호선에 악영향을 주는 것을 말한다.  |
| **ONU(Optical Network Unit)** | 미디어 컨버터와 같이 전기 신호를 광신호로 변환하는 장치이다. 이 변환 기능과 더불어 전화국의 olt와 연대하여 신호의 충돌을 방지하는 기능도 가지고 있는데, 이 장치를 '종단 장치'라고도 부른다. 종단 장치라는 말이 ONU와 미디어 컨버터를 구별하지 않은 통칭으로 사용되고 있기 때문이다. |
| **RADIUS** | Remote Authentication Dial-in User Service |
| **RAS** | Remote Access Server |
| **CHAP** | Challenge Handshake Authentication Protocol |
| **PAP** | Password Authentication Protocol |
| **PPPoA** | Point-to-Point over ATM |
| **DHCP** | Dynamic Host Configuration Protocol |
| **POP(Point Of Presence)** | 사용자가 계약한 프로바이더의 설비 |
| **방화벽** | 네트워크를 외부에서의 공격으로부터 지키기 위해 고안된 구조의 하나로서 이런 종류의 구조 중에는 최초로 등장한 것이다. 현재는 이 구조를 빠져나가는 공격 수법이 많이 출현했기 때문에 방화벽과 더불어 바이러스 검사, 부정 침입 검사, 검역 네트워크 등의 구조를 함께 사용하는 것이 보통이다. |
| **프록시** | 클라이언트와 웹 서버 사이에 설치하여 액세스 동작을 중개하는 구조 |
| **CDS(Content Delivery Service)** | 캐시 서버를 설치하고 캐시 서버를 웹 서버 운영자에게 대출하는 서비스 |
| **CDSP(Content Delivery Service Provider)** | 캐시 서버를 설치하고 캐시 서버를 웹 서버 운영자에게 대출하는 서비스를 제공하는 사업자 |
| **멀티태스크** | OS가 갖추고 있는 기능의 하나로, 복수의 태스크(프로그램)를 동시에 함께 실행하는 기능을 말한다. 하나의 프로세서는 어떤 시점에서 하나의 태스크만 실행할 수 있지만, 단시간에 태스크를 전환하면서 실행하므로 동시에 실행하는 것처럼 보인다. OS의 종류에 따라서는 '멀티프로세스'라고도 부른다. |
| **멀티스레드** | 멀티태스크와 같이 복수의 스레드를 동시에 함께 실행하는 기능을 가리킨다. 멀티태스크와 멀티스레드의 차이점은 태스크와 스레드의 차이라고 할 수 있다. OS의 내부에서 태스크는 하나하나 별도의 프로그램으로 취급되지만, 스레드는 한 개의 프로그램 속을 몇 개의 부분으로 나눈 것으로 취급된다. |
