## <a id="ch01"></a>Chapter 01 웹 브라우저가 메시지를 만든다 <sub>- 웹 브라우저의 내부 탐험</sub>

### 1. HTTP 리쿼스트 메시지를 작성한다

1. URL입력부터 시작한다.
2. 브라우저는 먼저 URL을 해독한다.
3. HTTP 리퀘스트 메시지를 만든다.

### 2. 웹 서버의 IP주소를 DNS 서버에 조회한다

1. Socket 라이브러리가 IP주소를 찾는 기능을 제공한다.
2. 리졸버를 이용하여 DNS서버를 조회한다.

### 3. 전 세계의 DNS 서버가 연대한다

1. DNS 서버의 기본 동작

조회 메시지에 포함된 정보<br>
(1) 이름 <br>
(2) 클래스<br>
(3) 타입<br>

DNS 서버는 서버에 등록된 도며엔명과 IP 주소의 대응표를 조사하여 IP 주소를 회답한다.

2. 도메인의 계층<br>
DNS에서 취급하는 이름은 www.lab.cyber.co.kr처럼 점으로 구분되어 있는데, 이 점이 계층을 구분한다. 이는 'com사업부 cyber부 lab과의 www'라는 이름과 같다. 이처럼 하나의 부서에 해당하는 것을 도메인이라고 한다.

3. 담당 DNS 서버를 찾아 IP주소를 가져온다.<br>
com이나 kr이라는 최상위 도메인의 상위에 루트 도메인이라는 도메인이 있다. 클라이언트와 가장 가까이 있는 DNS 서버에 웹 서버에 관한 정보를 조회하고, 이름이 등록되어 있지 않으면 도메인의 계층을 취로부터 차례로 따라간다. 가장 가까운 DNS 서버에는 루트 도메인의 DNS서버가 등록되어 있으므로 루트 도메인의 DNS서버에 클라이언트로부터 받은 조회 메시지를 전송한다.

4. DNS 서버는 캐시 기능으로 빠르게 회답할 수 있다.<br> 
DNS서버는 한 번 조사한 이름을 캐시에 기록할 수 있는데, 조회한 이름에 해당하는 정보가 캐시에 있으면 그 정보를 회답하기 때문이다.

### 4. 프로토콜 스택에 메시지 송신을 의뢰한다

1. 데이터 송·수신 동작의 개요<br>
OS 내부의 프로토콜 스택에 메시지 송신 동작을 의뢰할 때는 Socket 라이브러리 프로그램 부품을 결정된 순번대로 호출한다.
<br>
(1) 소켓을 만든다(소켓 작성 단계)<br>
(2) 서버측의 소켓에 파이프를 연결한다(접속 단계)<br>
(3) 데이터를 송·수신한다(송·수신 단계).<br>
(4) 파이프를 분리하고 소켓을 말소한다(연결 끊기 단계)

2. 소켓의 작성 단계<br>
소켓 라이브러리의 socket이라는 프로그램 부품만 호출하면 된다.<br>
애플리케이션은 '디스크립터'라는 번호표 같은 것으로, 소켓을 식별한다.

3. 파이프를 연결하는 접속 단계<br>
애플리케이션은 Socket 라이브러리의 connect라는 프로그램 부품을 호출하여 만든 소켓을 서버측의 소켓에 접속하도록 프로토콜 스택에 의뢰하는 동작을 실행한다.<br>
• 디스크립터: 애플리케이션이 소켓을 식별하는 것<br>
• IP 주소와 포트 번호: 클라이언트와 서버 간에 상대의 소켓을 식별하는 것

4. 메시지를 주고 받는 송·수신단계<br>
소켓에서 데이터를 보내면 상대측의 소켓에 데이터가 도착한다. 이를 위해 애플리케이션은 Socket라이브러리를 통해 프로토콜 스택에 디스크립터와 송신 데이터를 지정하고, write라는 프로그램 부품을 호출해서 프로토콜 스택이 송신 데이터를 서버에 송신한다. 그러면 서버는 수신 동작을 실행하여 받은 데이터의 내용을 조사하고 적절한 처리를 실행하여 응답 메시지를 반송한다.

5. 연결 끊기 단계에서 송·수신이 종료된다
브라우저가 데이터 수신을 완료하면 송·수신 동작은 끝난다. 그 후 Socket 라이브러리의 close라는 프로그램 부품을 호출하여 연결 끊기 단계로 들어가도록 의뢰한다. 그러면 소켓 사이를 연결한 파이프가 분리되고 소켓도 말소된다.

## <a id="ch02"></a>Chapter 02 TCP/IP의 데이터를 전기 신호로 만들어 보낸다 <sub>- 프로토콜 스택과 LAN 어댑터의 탐험</sub>

### 1. 소켓을 작성한다

#### (1) 프로토콜 스택의 내부구성

```text
┌── 애플리케이션
|   ├── 네트워크 애플리케이션(웹 브라우저, 메일러, 웹 서버, 메일 서버 등)
|   └── Socket 라이브러리(리졸버)
├── OS
|   └── 프로토콜 스택
|       ├── TCP 
|       ├── UDP
|       └── IP(패킷 운반, 경로 결정)
|           ├── ICMP
|           └── ARP
├── 드라이버 소프트웨어
|   └── LAN 드라이버(LAN 어댑터 제어)
└── 하드웨어
    └── LAN 어댑터: 케이블에 대해 신호를 송·수신하는 동작을 실행
```

• 브라우저나 메일 등의 일반적인 애플리케이션이 데이터를 송·수신할 경우에는 TCP<br>
• DNS서버에 대한 조회 등에서 짧은 제어용 데이터를 송·수신할 경우에는 UDP

#### (2) 소켓의 실체는 통신 제어용 제어 정보

프로토콜 스택은 소켓에 기록된 제어 정보를 참조하면서 움직인다.<br>

#### (3) Socket을 호출했을 때의 동작

1. socket을 호출하여 소켓을 만든다.<br>
- 소켓을 만들 때 한 개의 메모리 영역을 확보하고 초기 상태라는 것을 메모리 영역에 기록한다.
- 소켓이 만들어지면 소켓을 나타내는 디스크립터를 애플리케이션에 알려준다.
- 디스크립터를 받은 애플리케이션은 프로토콜스택에 데이터 송·수신 동작을 의뢰할 때 디스크립터를 통지한다.

### 2. 서버에 접속한다

#### 1. 접속의 의미

소켓을 만들면 애플리케이션(브라우저)은 connect를 호출한다. 그러면 프로토콜 스택은 자기쪽의 소켓을 서버측의 소켓에 접속한다.

#### 2. 맨 앞 부분에 제어 정보를 기록한 헤더를 배치한다

통신 동작에 이용하는 제어 정보는 다음의 두 종류이다.<br>
• 헤더에 기입되는 정보<br>
• 소켓(프로토콜 스택의 메모리 영역)에 기록되는 정보

#### 3. 접속 동작의 실체
접속 동작의 첫 걸음은 TCP 담당 부분에서 접속을 나타내는 제어 정보를 가록한 TCP헤더를 만드는 것이다. 그리고 TCP 헤더의 송신처와 수신처의 포트 번호로 접속하는 소켓을 지정한다.

### 3. 데이터를 송·수신한다

#### 1. 프로토콜 스택에 HTTP 리퀘스트 메시지를 넘긴다

• MTU: 패킷 한 개로 운반할 수 있는 디지털 데이터의 최대 길이. 이더넷에서는 보통 1,500바이트<br>
• MSS: 헤더를 제외하고 한 개의 패킷으로 운반할 수 있는 TCP의 데이터의 최대 길이

#### 2. 데이터가 클 때는 분할하여 보낸다

#### 3. ACK번호를 사용하여 패킷이 도착했는지 확인한다
시퀀스 번호를 통해 누락이 없는 것을 확인하면 수신측은 그 이전에 수신한 데이터와 합쳐서 데이터를 몇 번째 바이트까지 수신한 것인지 계산하고, 그 값을 TCP 헤더의 **ACK 번호**에 기록하여 송신측에 알려준다. 이 ACK 번호를 되돌려 주는 동작을 **수신 확인 응답**이라고 부르며, 송신측은 이것을 통해 상대가 어디까지 수신했는지 파악한다.

시퀀스 번호와 ACK 번호로 패킷이 수신측에 도착한 것을 확인한다.

#### 4. 패킷 평균 왕복 시간으로 ACK 번호의 대기 시간을 조정한다

ACK 번호가 돌아오는 시간을 기준으로 대기시간을 판단한다.

#### 5. 윈도우 제어 방식으로 효율적으로 ACK 번호를 관리한다

윈도우 제어는 한 개의 패킷을 보낸 후 ACK번호를 기다리지 않고 차례대로 연속해서 복수의 패킷을 보내는 방법이다. 그러면 ACK 번호가 돌아올 때까지의 시간이 낭비되지 않는다.

수신 간으한 데이터 양의 최대값을 윈도우 사이즈라고 부르며, TCP를 정밀조정하는 매개변수의 하나로 알려져 있다.

## <a id="ch07"></a>📚 핵심 용어 사전

| Term & Category | Definition, Role & Example |
| :--- | :--- |
| **URL** | Uniform Resource Locator |
| **FTP(File Transfer Protocol)** | 파일을 업로드하거나 다운로드할 때 사용하는 프로토콜. FTP 프로토콜을 이용하여 파일 전송을 하는 프로그램도 'FTP'라고 한다. |
| **도메인명** | `www.cyber.co.kr`과 같이 마침표로 구분하여 표현하는 이름 |
| **포트 번호** | 액세스 대상 서버 애플리케이션을 지정하여 사용하는 번호 (e.g., 웹이라면 `80`번, 메일이라면 `25`번) |
| **HTTP** | HyperText Transfer Protocol |
| **프로토콜** | 통신 동작의 규칙을 정한 것 |
| **디렉토리** | 디렉토리는 윈도우에서 '폴더'와 같은 의미의 용어 |
| **URI** | Uniform Resource Identifier |
| **CGI 프로그램** | 웹 서버 소프트웨어에서 프로그램을 호출할 때의 규칙을 정한 것. CGI의 규칙에 맞게 움직이는 프로그램을 'CGI 프로그램'이라고 한다. |
| **폼** | 웹 페이지에 있는 텍스트 입력 상자나 체크박스 등이 표시된 부분 |
| **태그** | 웹 페이지를 쓸 때 이용하는HTML이라는 문법에서 결정된 제어 정보. 예를 들어 문장 안에 영상을 포함한 경우에는 ```<img src="image.jpg">```라는 형태의 태그를 문장에 포함시킨다. |
| **라우터** | 패킷을 중계하는 장치의 일종 |
| **허브** | 패킷을 중계하는 장치의 일종이며, 리피터 허브와 스위칭 허브의 두 가지 유형이 있다. |
| **DNS(Domain Name System)** | 서버명과 IP주소를 대응시키기 위해 DNS를 가장 많이 사용하지만, DNS의 기능은 다양하다. 메일 주소와 메일 서버를 대응시키는 것 등 다양한 정보를 이름에 대응해서 등록할 수 있다. |
| **리졸버(resolver)** | DNS 서버에 조회 메시지를 보내는 프로그램 |
| **프로토콜 스택** | OS 내부에 내장된 네트워크 제어용 소프트웨어. '프로토콜 드라이버', 'TCP/IP 소프트웨어' 등으로도 부른다. |
| **MX(Mail eXchange)** | 클라이언트에서 DNS서버로 보낸 조회메시지에 포함된 타입은 IP주소를 조회할 때는 A를 사용하지만, 메일 배송 목적지를 조회할 때는 MX를 사용한다.  |
| **캐시** | 한 번 사용한 데이터를 데이터의 이용 장소와 가까운 곳에 있는 고속의 기억 장치에 저장하여 두 번째 이후의 이용을 고속화하는 기술을 말한다. CPU와 메모리 사이에 두는 캐시 메모리나 디스크 장치의 데이터를 메모리에 캐시하는 방법 등을 이전부터 사용했는데, 네트워크에서도 캐시 기술에 의해 고속화하는 방법이 일반화되어 있다. |
| **소켓(socket)** | 클라이언트 프로그램과 서버 프로그램을 연결한 파이프의 양끝에 있는 데이터의 출입구(cf. Socket은 Socket 라이브러리를 가리킴) |
| **디스크립터** | 하나하나의 소켓에 할당한 번호 |
| **IP주소** | 네트워크에 존재하는 PC나 서버를 식별하기 위해 이용하는 주소 |
| **DNS 서버** | 웹 서버의 이름에서 IP 주소를 조사하기 위해 서용하는 서버 |
| **수신 버퍼** | 수신한 응답 메시지를 저장하기 위한 메모리 영역 |
| **패킷** | 네트워크에서 데이터는 수십 바이트에서 수천 바이트 정도의 작은 덩어리로 분할되어 운반된다. 이렇게 분할된 데이터의 덩어리를 패킷이라고 한다. |
| **ICMP** | 패킷을 운반할 때 발생하는 오류를 통지하거나 제어용 메시지를 통지할 때 사용 |
| **ARP** | IP 주소에 대응하는 이더넷의 MAC 주소를 조사할 때 사용한다. |
| **PID** | Process ID의 약자. 각 프로그램을 식별하기 위해 OS가 할당하는 번호. 작업관리자로 프로그램을 확인할 수 있다. |
| **시퀀스 번호** | TCP에서 데이터를 조각으로 분할할 때 조각이 통신 개시부터 따져서 몇 번째 바이트에 해당하는지를 세어서 TCP 헤더에 기록한 값 |
